# 资格规则

一条记录**四条满足任意一条**才收。全不满足就不写 —— 这个清单的主要作用是把大部分东西挡在外面。

## 四条

**1. 错误信念被推翻。**
你当时有理由相信那个错答案。区别：

- ✅ 收：「报错说『没有可用的凭据』，所以我以为要去登录账号；实际是 TLS 后端选错。」
- ❌ 不收：「我打错了一个字母。」

判据：**如果当时的你看到那段证据，会做出同样的错误推断吗？** 会，才收。

**2. 有可核对的数字或证据。**
时间、内存、行数、次数、成本、字节、退出码、报错原文。
「感觉快了很多」不算。

**3. 有代价。**
不处理会烧钱、丢数据、浪费几小时、或在生产中静默出错。
「知道也无所谓」的不收。

**4. 能迁移。**
换个项目、换门语言、换台机器，还会撞上同一个模式。
「这个库的 4.2 版本有个 bug」通常不迁移，除非它揭示的是一类接口设计问题。

## 明确不收

| 类型 | 为什么 |
|---|---|
| 语法错误、拼写错误 | 没有错误信念可言 |
| 装环境、配镜像、等下载 | 琐事，复现不了 |
| 网上抄来的标准做法 | 不是你的发现，没有 `wrong_belief` |
| 没有数字的「最佳实践」 | 无法核对 |
| 含真实 Key / token / 账号 / 内网地址 | 安全红线，无论多有价值 |
| 「今天学了 X」 | 那是笔记，不是事故 |

## 边界情况怎么判

**「我当时不知道，后来查到了」** —— 这不算错误信念被推翻。
区别在于：你当时**有没有根据手头证据做出一个推断**。有推断、推断错了，才收；纯空白，不收。

**「两个方案都行，我随便选了一个」** —— 不收。
有代价的取舍才收：「我选了 A 因为假设 QPS < 100，实测 3000，所以这个选择现在是错的。」

**同一类错误的第 N 次出现** —— 不要新建条目。
去改已有条目，并在 `追问会问什么` 里加一条「为什么这次又犯了」。**重复出现的错误说明规则没写清楚，是规则的 bug，不是你的。**

## 收进来之后

每条的 `status` 三选一：

| status | 含义 |
|---|---|
| `已掌握` | 能不看笔记复述原因和修法 |
| `需复习` | 记得结论，说不清原因 |
| `只见过一次` | 当时靠查资料解决，还没内化 |

`需复习` 和 `只见过一次` 是复习技能的输入。**只写不复习的笔记等于没写。**
