### 面试者自述的「面试焚诀」（照抄要点）

- 简历深挖不必多说；基础后端知识至少得能简单说清楚概念，不用长篇大论。
- 重点是 Skills、MCP、CLI 这些东西不能只会名词，得真的往深了搞明白。
- **Harness 的概念和实现一定要清楚。**
- 三个流行的 Agent 框架：Openclaw、Hermes、Claude code。面试官问起来要能撑住五分钟，至少把记忆机制、工具调用、上下文管理讲清楚并做对比；知道 CC 的 hook 是怎么实现的能加分。
- 回答框架：面试官问「记忆系统如何实现」，先讲自己项目里怎么做，再主动讲这三个框架怎么做。
- AI 写代码这块，平时怎么用、踩过什么坑，思考要有深度。
- 大厂面 agent 开发还需要开发之外的知识：llm、vlm 等模型的基本了解，甚至训练、推理、强化学习；像字节会希望往全栈发展。

### 21 道面试题（题目原文）

**一、Prompt 与输入理解**

1. Prompt Engineering 的核心目标是什么？为什么模型会对同一件事，换个说法效果差十倍？
2. System Prompt / Few-shot / Chain-of-Thought（CoT）在 Prompt 设计中有什么作用？
3. Token、上下文窗口和上下文腐化是什么？它们如何影响模型的理解和生成？

**二、模型输出控制**

4. 幻觉（Hallucination）是怎么产生的？你有哪些方法可以减轻模型幻觉？
5. 什么是 Structured Output？如何通过它控制模型输出？
6. Function Calling 与 RAG 的区别和联系是什么？什么时候用 Function Calling，什么时候用 RAG？
7. Embedding / 向量数据库在 RAG 中的作用是什么？如何设计检索策略？

**三、Agent 系统设计**

8. Agent 是如何结合工具、知识和规划自主运行的？
9. 多 Agent 架构下，主 Agent 和子 Agent 的通信链路应该如何设计？如何处理异常？
10. 如何解决 Agent 的上下文漂移问题？如何防止工具调用出现幻觉？
11. MCP（工具标准化接口）和 Skill（能力封装复用）在 Agent 系统中起什么作用？

**四、模型优化与训练**

12. 微调（Fine-tuning）和 RAG 的使用场景有什么区别？
13. SFT 和 RLHF 哪个更适合快速迭代？在基模能力越来越强的情况下，这两者的破局点是什么？
14. 如何降低推理成本？在多任务、多 Agent 系统中如何权衡效率和准确性？

**五、上下文与记忆管理**

15. 如何在有限的上下文窗口内放入关键内容？如何做短期和长期记忆压缩？
16. 混合路由和限流器在多 Agent 系统中为什么重要？

**六、工程落地与系统能力**

17. 项目中 Agent 的执行链路如何设计，如何保证连续任务的正确性？
18. 在长任务或复杂任务中，如何保证模型不会偏离原始目标？
19. 如何评估生图/生成模型的多样性和准确性？
20. 如何处理工具调用的安全问题（如 Key 泄露、敏感信息暴露）？
21. 结合开发经历，谈谈传统 Web 应用和 AI Agent 应用有什么不同？

同组还有：Agent 系统如何设计能力复用和 Skill 管理，保证可扩展性？

### 文中出现的关键数值与术语（照抄）

- RRF（倒数排名融合）用于合并向量检索与关键词检索结果
- Chunk 一般 512–1024 Token，带 50–100 Token 重叠；HyDE（先让模型生成假答案去检索）；Rerank 用 Cross-Encoder，Bi-Encoder 只管快
- 降本手段：混合路由（简单任务小模型、复杂推理大模型）、KV Cache、量化（FP16 → INT8/INT4）、批处理
- 限流器一般用令牌桶算法（平均速率 + 突发上限），关键路径请求优先
- 分层记忆：短期记忆放上下文、长期记忆放向量数据库、工作记忆放 System Prompt
- 材料对 Agent 的定义：Agent 的本质 = 思维链 + Function Calling + 循环；关键是「模型自己决定下一步做什么，不需要人逐步指挥」

### 材料中值得单独拎出来的立场（照抄其意）

- SFT 的破局点是数据质量而非数量；RLHF 的破局点是从人工标注走向自动反馈（Verifiable Reward）
- 传统 Web 是确定性的、Agent 是概率性的；Agent 很难写确定性测试，更多是评估指标 + Bad Case 分析
